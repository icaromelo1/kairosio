# Code review geral — 30/07/2026

Revisão completa das duas bases (`kairos-api` ~2.9k linhas, `kairos-ui` ~8.1k),
em ciclos de review → fix → re-review até uma passada sem achados novos.
Branch: `fix/code-review-geral`.

## Achado que escondia os outros

O `tsconfig.json` da UI não declarava o alias `@/*` (só o `vite.config.ts` tinha).
`vue-tsc` reportava **90 erros falsos** de "Cannot find module '@/...'" — e, no meio
deles, 7 erros reais passavam batido. Com o alias declarado, os 90 sumiram e os 7
reais foram corrigidos. **`npm run typecheck` era um gate morto.**

## Segurança

| Onde | Problema | Correção |
|---|---|---|
| `PUT /character`, `PUT /world/state` | `@Body() any` → `Object.assign`: cliente podia mandar `id` e sobrescrever a linha de **outro** usuário via `repo.save`, ou setar `photoFile` arbitrário | DTOs com whitelist (enums, hex, tamanho) |
| `GET /auth/me` | devolvia a entity `User` crua — **hash bcrypt incluso** | `select` explícito sem `password` |
| Socket `handshake` | sem token conectava e entrava nas salas `public:*` junto com convidados reais | desconecta se não houver usuário válido |
| `join` do socket | `name`/`avatar` iam sem validação pra todos os clientes; `photoUrl` era URL externa arbitrária que todos baixavam | sanitização whitelist + `photoUrl` reescrita pro caminho canônico da API |
| `POST /feedback` | público e confiando no `email` do corpo → qualquer visitante abria feedback **em nome de outra pessoa** | exige JWT, autor sai do token |
| `GET /feedback` | público expondo `authorEmail` inteiro + `authorId` | email mascarado no servidor, `authorId` fora da resposta |
| `POST /jukebox/sync` | público, dispara Drive + yt-dlp em série | admin-only (`ADMIN_EMAILS`) |
| `JWT_SECRET` | fallback `'kairos-secret'` em 3 lugares (assinável por qualquer um se a env faltasse) | `jwt-secret.ts` único, obrigatório em produção |
| `jwt.strategy` | token de usuário apagado (convidado pós-logout) seguia válido | `UnauthorizedException` se o usuário não existe |
| `register` | aceitava `@github.local` — sufixo do fallback OAuth GitHub → account takeover quando o OAuth ativar | sufixo bloqueado |
| `jukeboxAdd` | sem cooldown nem cap → spam de yt-dlp na VM | fila máx. 50 + cooldown 5s (só pra download novo) |
| lousa | `objectId` livre criava lousas infinitas na memória | cap 50/sala, `objectId` ≤64 sem `:` |

## Bugs

- **Sentar travava o personagem em definitivo.** Cadeira/sofá do editor são
  `solid: true` e o sentar teleportava pro centro do objeto — `isSolid` bloqueava
  toda saída. Agora guarda a posição anterior, restaura ao levantar, e existe uma
  regra de escape (tile atual sólido → movimento liberado).
- **Avatar remoto malformado derrubava a sala inteira.** `HAIR[hairStyle]`
  undefined lançava dentro do ticker do Pixi, a cada frame, pra todos. Agora o
  look remoto é sanitizado com defaults.
- **Reconexão devolvia o player pro mapa antigo** (re-`join` usava os `opts`
  originais). O estado do join agora acompanha `switchMap`/`emitMove`.
- **Leaks de Pixi**: `removeChildren()` não destrói no Pixi 8 — cada troca de
  mundo e cada `pointermove` do editor (ghost) vazava `Graphics`.
- **Sala vazia seguia consumindo recursos**: o timer do jukebox continuava
  avançando música pra ninguém; fila e modo de voz nunca eram descartados.
- **`AudioContext` por peer**: Safari limita a ~4 — o indicador de fala morria em
  sala cheia. Agora é um contexto compartilhado.
- **Voz reconectava em loop** na borda do raio de proximidade → histerese
  (conecta a ≤4 tiles, só derruba a >5).
- `task`/`note` sem org ativa estouravam 500 (NOT NULL) → lista vazia + mensagem
  clara no create.
- `PUT /org` sem `name` crashava no `slugify(undefined)`; admin podia se rebaixar
  sendo o último admin e travar a org; convidado criava org órfã.
- Feedback: `setInterval` sem cleanup; jukebox não reiniciava a mesma música
  duas vezes seguidas na fila; `boardState` sem `objectId` misturava lousas.

## Validação

Bateria de smoke contra a API compilada (Postgres descartável), confirmando cada
correção de segurança na resposta real — `/auth/me` sem `password`, `id` do corpo
ignorado, socket anônimo desconectado, `name` capado em 40, avatar hostil chegando
vazio no outro cliente, autoria do feedback vindo do token. `vue-tsc`, `tsc`,
`jest` e `vite build` limpos.
